# 表から付箋ツール

表データから付箋を生成し、一覧表示・検索・絞り込みができるブラウザアプリです。
学校名、担当者名、分類などの項目を使って必要な付箋だけを表示し、表示する項目や並び順も調整できます。

HTMLファイル単体で動作するため、サーバーを用意せずにブラウザで利用できます。データの読み込みや検索などの処理は、基本的に利用中のブラウザ内で行われます。

## 主な用途

- 表形式で管理している情報を、付箋形式で見やすく表示する
- 学校名などの項目で絞り込み、必要な情報だけを確認する
- キーワード検索で該当する付箋をすばやく探す
- 絞り込み後のデータや作業状態をJSONとして保存する
## 主な機能

| 分類 | 機能 || --- | --- || データ入力 | 表データの読み込み、Excel読み込み、JSON読み込み || 表示 | 読み込んだデータを付箋として表示 || 絞り込み | 学校名など、項目ごとのフィルター || 検索 | キーワード検索、検索一致箇所のハイライト || 表示設定 | 表示項目の選択、表示項目の並べ替え || 保存 | 通常のJSON保存、現在の作業状態の保存 || 分割保存 | 指定した項目の値ごとの個別JSON保存 || 安全確認 | 保存前のファイル数・件数確認 || 入力方法 | JSONファイルのドロップ読み込み |

### 保存に関する特徴

- JSON保存では、現在表示中の絞り込み済みデータだけを保存します。
- 保存したJSONには、表示項目、表示項目の並び順、検索条件、各種フィルターなどの作業状態も含められます。
- 保存したJSONを読み込むと、保存時点のデータと作業状態を復元できます。
- 「項目ごとに保存」では、指定した項目の値ごとに個別のJSONファイルを作成します。
- 例えば学校名を指定すると、`〇〇小.JSON` や `〇〇小.JSON` のように値ごとのファイルをダウンロードします。
- 指定項目の値が空欄の場合は、`未設定.JSON` として保存します。
## はじめて使う人向けの使い方

1. ブラウザでアプリを開きます。
2. 表データ、Excelファイル、またはJSONファイルを読み込みます。JSONファイルは、読み込み欄へのドロップでも読み込めます。
3. 読み込んだデータが付箋として表示されたことを確認します。
4. 表示したい項目を選び、必要に応じて表示項目の順番を並べ替えます。
5. 学校名などの項目別フィルターを選択し、表示対象を絞り込みます。
6. 検索欄にキーワードを入力して検索します。一致した箇所はハイライト表示されます。
7. 必要なデータだけが表示されていることを確認します。
8. JSON保存、作業状態の保存、または「項目ごとに保存」を選びます。保存前にファイル数と件数を確認してください。

## 入力データの想定

- 表データは、1行を1件のデータ、列を項目として扱える形式を想定しています。
- 各列には、学校名、担当者、分類、状態など、内容が分かる項目名を設定してください。
- フィルターで使う項目名は、アプリに固定された名称ではなく、実際に読み込んだデータの項目名に合わせて選びます。
- JSONは、アプリで表として扱える形式のデータを用意してください。既存のJSONを読み込む場合は、まず少量のデータで表示結果を確認すると安心です。

```json
[{"学校名":"〇〇小","担当者":"山田","状態":"確認中"}]
```
## JSONの読み込みと保存について

### JSONを読み込むときの注意

JSONの読み込みは、現在のデータへの追加ではありません。読み込んだJSONの内容だけに置き換わります。現在のデータを残したい場合は、先にJSON保存などで保存してください。

保存したJSONを読み込むと、保存時点で表示されていた絞り込み済みデータに加えて、表示項目、表示項目の並び順、検索、フィルターなどの作業状態も復元できます。

複数の値ごとにファイルを作成する場合は、「項目ごとに保存」を使います。保存対象の項目として学校名を選ぶと、学校ごとに個別のJSONファイルが作成されます。空欄のデータは`未設定.JSON`にまとめられます。

## GitHub Pagesなどで公開する方法

1. GitHubで新しいリポジトリを作成します。公開範囲は、扱うデータの内容に合わせて設定してください。
2. アプリのHTMLファイルをリポジトリに配置します。必要に応じて、公開時の入口になるHTMLファイルを`index.html`という名前でリポジトリ直下に置きます。
3. 変更をコミットしてGitHubへ反映します。
4. リポジトリのSettingsからPagesを開き、公開元として対象のブランチとフォルダーを選択して保存します。
5. Pagesの設定画面に表示された公開URLを開き、アプリが表示されることを確認します。

HTMLファイル単体で動作する構成であれば、追加のサーバー処理なしで公開できます。
## 注意事項

- 「項目ごとに保存」などで複数ファイルを同時にダウンロードすると、ブラウザが複数ダウンロードをブロックする場合があります。その場合は、ブラウザの許可やダウンロード設定を確認してください。
- 公開サイト上で個人情報、児童・生徒に関する情報、連絡先、社内情報、その他の機密情報を扱う場合は、公開範囲とアクセス権限を十分に確認してください。
- GitHub Pagesなどの公開URLで扱うデータは、URLを知っている人が閲覧できる可能性があります。公開用データと業務用データを分けてください。
- データの読み込み、検索、絞り込みはブラウザ内で処理されますが、利用するブラウザや公開環境の設定も確認してください。
- 重要なデータは、作業前後に別の場所へバックアップしてください。

## 開発・カスタマイズ

HTMLファイルを編集できる環境があれば、画面の見た目、付箋の表示内容、項目の初期設定、検索やフィルターの動作などを用途に合わせてカスタマイズできます。変更後は、まずローカルのブラウザで読み込み・検索・保存・復元を確認してから公開してください。

利用しているデータ形式やブラウザによって動作が異なる場合があるため、実際に使うデータのサンプルで動作確認することをおすすめします。
